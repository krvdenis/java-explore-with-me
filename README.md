# ExploreWithMe (EWM) — Платформа для организации и поиска событий

Микросервисное бэкенд-приложение на базе Spring Boot, представляющее собой сервис-агрегатор для создания мероприятий и автоматизации сбора локальных сообществ. Позволяет пользователям предлагать свои события, искать компании для совместного досуга, а администраторам — модерировать контент, управлять регистрацией пользователей и контролировать потоки данных.

## 🚀 Ключевые архитектурные фичи

*   **Микросервисная архитектура:** Проект разделен на два независимых приложения, общающихся по REST API через `RestTemplate`:
    1.  `main-service` — содержит всю бизнес-логику (пользователи, категории, события, запросы на участие, комментарии к событиям, подборки событий).
    2.  `stats-service` — выделенный сервис, который собирает, хранит и анализирует данные о просмотрах публичных страниц связанных с событиями.
*   **Stateless REST API & JWT Security:** Система безопасности спроектирована по принципу Token-based аутентификации с использованием библиотеки JJWT 0.12. Приложение полностью независимо от состояния сервера (Stateless): аутентификация клиентов выполняется путем валидации криптографической подписи токена, передаваемого в заголовке Authorization: Bearer <token>. Это исключает накладные расходы на хранение сессий и обеспечивает архитектурную готовность системы к горизонтальному масштабированию.

*   **Многоуровневое API:** Логика и контроллеры разделены на три слоя доступа для изоляции прав и безопасности:
    *   `Public API` — доступен без авторизации. Позволяет искать опубликованные события, просматривать категории, подборки событий, комментарии к событиям и фиксирует каждый просмотр событий в сервисе статистики.
    *   `Private API` — доступен авторизованным пользователям (защищен JWT). Позволяет создавать события, отправлять заявки на участие, оставлять комментарии к событиям и управлять своими запросами и событиями.
    *   `Admin API` — защищенный интерфейс для модераторов, позволяющий одобрять/отклонять публикации и регистрацию пользователей, управлять категориями, пользователями, подборками событий и комментариями к событиям.
*   **Динамическая фильтрация (Querydsl):** Поиск событий на публичном и административном уровнях реализован через `Querydsl`. Это позволило гибко комбинировать десятки параметров (даты, способ сортировки, категории, текстовый поиск и тд.) в один эффективный запрос без написания избыточного SQL-кода.
*   **Транзакционные email-уведомления (Spring Mail):** Реализовал подсистему почтовых уведомлений, интегрированную с процессом создания аккаунтов. Приложение автоматически генерирует и отправляет приветственное email-письмо пользователю сразу после подтверждения или отклонения администратором регистрации на платформе, подтверждая создание учетной записи.


## 🛠️ Технологический стек

*   **Язык:** Java 21
*   **Фреймворки:** Spring Boot 3.x (Spring Web, Spring Data JPA, Hibernate, Spring Security)
*   **Безопасность:** JWT (JJWT 0.12)
*   **Базы данных:** PostgreSQL (основная БД и БД статистики)
*   **Инструменты:** Querydsl, RestTemplate, Maven, Lombok
*   **Контейнеризация:** Docker, Docker Compose

## 🏗️ Схема базы данных и структура
Приложение работает с реляционной базой данных. Основные сущности:
*   `User` — пользователи системы.
*   `Event` — события (со статусами PENDING, PUBLISHED, CANCELED).
*   `Request` — заявки пользователей на участие в событиях (с валидацией лимитов мест).
*   `Category` — тематические категории мероприятий.
*   `Comment` — комментарии к событиям.
*   `Compilation` — подборки событий.
*   `RegistrationRequest` — запрос на регистрацию пользователя.

## 💻 Локальный запуск (Docker)

Проект полностью контейнеризирован и готов к запуску одной командой. Убедитесь, что у вас установлены Docker.

1. Клонируйте репозиторий:
```bash
git clone git@github.com:krvdenis/java-explore-with-me.git
cd java-explore-with-me
```

2. Соберите проект и запустите контейнеры (автоматически поднимутся микросервисы и базы данных PostgreSQL):
```bash
docker compose up --build
```

После успешного запуска:
* Основной сервис будет доступен по адресу: `http://localhost:8080`
* Сервис статистики будет доступен по адресу: `http://localhost:9090`

## 📊 Выводы по результатам проекта

* **Успешно реализована распределенная микросервисная архитектура:** Вынос сбора статистики в изолированный сервис полностью защитил основную бизнес-логику платформы от деградации производительности при обработке большого количества фоновых просмотров страниц.
* **Обеспечена безопасность данных по канонам REST:** Переход к полностью Stateless-архитектуре на базе JWT-токенов исключил накладные расходы оперативной памяти сервера на хранение сессий.
* **Оптимизирована кодовая база для поисковых алгоритмов:** Интеграция Querydsl устранила необходимость написания громоздких SQL-запросов вручную, снизила риск ошибок при фильтрации и сократила время на добавление новых бизнес-критериев поиска.
